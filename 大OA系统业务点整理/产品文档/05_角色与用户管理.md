# 角色与用户管理 

## 角色管理 (Role Management)



### 1. 页面逻辑与交互 (UI Interactions)

- **列表渲染：**
  - **数据范围：** 仅展示**当前企业（Current Subject）**下的自定义角色。
  - **字段映射：** 序号、角色名称、角色说明、创建日期、最后更新时间。
- **查询区：**
  - **模糊搜索：** 支持按“角色名称”模糊匹配。
  - **日期筛选：** 按“更新时间”范围筛选。
  - **重置：** 清空所有筛选条件并重新加载列表。
- **添加角色 (Add Role)：**
  - 点击“+ 添加角色”按钮，弹出模态框 (Modal)。
  - 输入：角色名称（必填）、角色说明（选填）、权限树勾选（必填）。
  - 保存后列表自动刷新。
- **操作列功能：**
  - **编辑角色：** 修改名称和说明。
  - **权限管理 (Permission)：** 抽屉展示权限配置页，勾选该角色对应的菜单/按钮权限树。
- **批量删除：**
  - 勾选左侧复选框后，“删除角色”按钮高亮可用。
  - 点击删除需二次确认：“确定要删除选中的 X 个角色吗？”

### 2. 字段数据字典 (Data Constraints)

| **字段**     | **约束条件**      | **逻辑说明**                                                 |
| ------------ | ----------------- | ------------------------------------------------------------ |
| **角色名称** | 必填，2-20字符    | **唯一性校验：** 同一企业下角色名不可重复。提示：角色名称不可重复/ |
| **角色说明** | 选填，最大200字符 | 用于备注职能。                                               |

### 3. 异常与边界场景 (Edge Cases)

- **删除被引用的角色：**
  - 若某角色（如“财务经理”）下已经关联了成员，**禁止删除**。
  - **报错提示：** “该角色下存在关联成员，请先解除关联后再删除。”
- **系统预设角色：**
  - 列表中不包含系统初始化生成的“初始管理员”角色。

------

- - 对其进行编辑，只能执行“移除”操作。

## 用户管理 (User Management)



### 1. 页面布局与交互 (UI Interactions)

#### A. 左侧：组织架构树 (Dept Tree)

- **默认状态：** 展开至第三级，默认选中根节点（公司名）。
- **交互：**
  - **点击节点：** 右侧列表刷新，仅显示该部门（及其子部门）下的用户。
  - **添加部门：** 点击顶部“添加部门”按钮，在当前选中节点下创建子部门。
  - **刷新图标：** 点击后重新加载最新的组织树结构。

#### B. 右侧顶部：部门信息栏

- **动态展示：** 显示当前选中部门的名称、总人数、**部门主管姓名**。
- **逻辑：** 若当前部门无主管，显示“部门主管：暂无”。

#### C. 右侧列表：成员管理

- **筛选项字段**：

  - 位于右侧列表顶部的组合查询栏。

    筛选字段定义

    | **字段组件** | **类型** | **占位符/默认值** | **逻辑说明**                                                 |
    | ------------ | -------- | ----------------- | ------------------------------------------------------------ |
    | **用户姓名** | 输入框   | `请输入用户姓名`  | **模糊查询** (Like %Name%)。支持输入中文或拼音。             |
    | **手机号**   | 输入框   | `请输入手机号`    | **后模糊查询** (Like 138%) 或精准查询。支持输入部分数字。    |
    | **用户角色** | 下拉选择 | `请选择用户角色`  | **单选/多选** (建议单选)。数据源来自“角色管理”页配置的角色列表。 |

    按钮交互逻辑

    - **查询 (Search)：**
      - **触发：** 点击按钮。
      - **范围逻辑 (Scope)：**
        - **默认：** 在**当前选中的部门**（及其子部门）范围内进行搜索。
      - **结果处理：** 列表刷新，展示符合条件的用户。底部翻页器重置为第 1 页。
    - **重置 (Reset)：**
      - **触发：** 点击按钮。
      - **效果：**
        1. 清空“姓名”、“手机号”输入框内容。
        2. 重置“用户角色”下拉框为“全部/未选择”。
        3. **列表刷新：** 重新加载当前部门下的全量用户列表。

    边界场景 (Edge Cases)

    - **搜索无结果：**
      - 当查询条件组合下没有匹配数据时。
      - **显示：** 列表区域显示 Empty State（空状态插画），文案提示“未找到符合条件的用户”。
    - **联动逻辑：**
      - 如果在搜索结果展示状态下，用户点击了左侧**组织树的另一个部门**。
      - **预期行为：** 自动**清空**右侧的搜索条件（重置），并显示新选中部门的全量数据。这是为了避免用户困惑（为什么切换了部门还是没数据？原来是搜索条件还在）。

- **列表字段：**

  - **姓名（含标签）：** 若该用户是当前部门主管，姓名后需显示橙色 `主管` Badge。
  - **手机号、部门、角色、添加时间。**

- **操作列功能：**

  - **编辑：** 修改部门、角色。
  - **设为主管 (Set Manager)：**
    - 点击后，该用户成为当前部门主管。
    - **互斥逻辑：** 原主管自动被撤销（一个部门仅一个主主管）。
    - 列表自动刷新，“主管”Badge 转移到该用户名字后。
  - **删除 (Remove)：**
    - **定义：** 这是**“主体解绑”**（离职），非平台销号。
    - **交互：** 点击弹出警示“确定将该成员移出当前企业吗？该操作不可恢复。取消/确认”

#### D. 添加用户 (Add User)/编辑用户（Edit User）

- **入口：** 点击蓝色“添加用户”按钮。或列表点击“编辑”
- **交互流程：**
  1. 输入手机号（必填）、姓名（必填）、选择部门（必填）、选择角色（必填）。
  2. **后端校验：** 检查手机号是否已存在于平台 `Account` 表。
     - **已存在：** 直接建立关联，用户下次登录可看到该企业。
     - **未存在：** 自动创建账号，并建立关联。

### 2. 字段数据字典 (Data Constraints)

| 字段       | 约束         | 说明                           |
| ---------- | ------------ | ------------------------------ |
| **手机号** | 必填，11位   | 企业的唯一识别键。             |
| **姓名**   | 必填，1-10位 | 用户姓名，支持中文             |
| **部门**   | 必选         | 必须归属至少一个部门。         |
| **角色**   | 必选，多选   | 用户可同时兼任“财务”和“行政”。 |



### 3. 异常与边界场景 (Edge Cases)

- **删除部门：**
  - 若部门下还有成员或子部门，**禁止删除**，提示“请先清空部门下成员”。
- **重复添加：**
  - 若输入的手机号已是当前企业成员，提示“该成员已存在”。
- **删除主管：**
  - 若删除的用户是“部门主管”，系统提示：“当前用户是部门主管，请更换部门主管后删除”。

## 全局账号管理 (Global Account Center)

该页面仅平台级超级管理员可见，用于处理紧急情况

### 1. 页面逻辑与交互 (UI Interactions)

- **筛选项**：
  - 用户姓名：精准查询
  - 手机号：精准查询
  - 账号状态：正常、停用
  - 企业：下拉。系统维护

- **列表渲染：**
  - **展示列：** 用户姓名、手机号、添加时间、**关联企业**（展示具体企业列表）、**账号状态**（正常/停用）。
  - 注意：若某个账号被所有的企业都删除，依然可展示；此时关联企业展示为空，显示符号——
  - 排序：添加时间倒序
- **核心操作列：**
  - **停用 (Freeze)：**
    - 仅对状态为“正常”的用户显示。
    - **交互：** 点击弹出**红色高危警示窗**。
    - **文案：** “⚠️ 警告：您正在执行平台级停用。该操作将导致该账号**无法登录任何关联企业**。确认执行？”取消/确认停用
  - **启用 (Unfreeze)：**
    - 仅对状态为“停用”的用户显示。
    - 点击后恢复正常。

### 2. 数据与权限 (Data & Permissions)

- **数据范围：** 平台所有注册账号（全量）。
- **特殊规则：**
  - 此页面**没有**“添加用户”按钮（用户总是通过企业邀请产生的）。
  - 此页面**没有**“编辑部门/角色”功能（这是企业内部事务，超管不干涉）。

### 3. 异常与边界场景 (Edge Cases)

- **并发登录阻断：**
  - 当点击“停用”确认的一瞬间，后端必须**强制销毁**该用户所有已颁发的 Access Token（踢下线）。
  - 用户下一次点击任何按钮时，接口返回 `401 Unauthorized (Account Disabled)`，前端强制跳转登录页。
