| 评论    | 前序审批人       | 通知   | 站内信             | "评论"项目名称：【项目名称】由【发起人】发起的【流程名称】，【评论人】发表了评论意见，请查阅。                                                |

### 通知原则

1. **待办和站内信不同时使用**：同一场景下，待办任务与站内信通知不重复发送。

## 添加用户短信通知规则

### 通知原则

- **短信中不得展示手机号**
- **短信中不得展示网址链接**
- 可说明“账号是您的手机号”，但不得在短信正文中展示具体手机号数字。

### 通知清单

| 序号 | 触发场景                   | 接收对象                    | 通知渠道 | 消息模板                                                            | 说明           |
| -- | ---------------------- | ----------------------- | ---- | --------------------------------------------------------------- | ------------ |
| 1  | 企业用户新增                 | 被添加的企业用户（不区分管理员/非管理员）   | 短信   | 尊敬的【姓名】，【操作人】已将您添加为【企业名称】的用户，请及时登录系统完成认证，账号是您的手机号，密码:【密码】，请妥善保管 | 含密码，需告知认证登录  |
| 2  | 企业用户添加至新企业（用户已在其他企业存在） | 被添加的企业用户（不区分管理员/非管理员）   | 短信   | 尊敬的【姓名】，【操作人】已将您添加为【企业名称】的用户，请及时登录系统完成认证，账号是您的手机号，请妥善保管         | 不含密码，需告知认证登录 |
| 3  | 企业用户调整为管理员             | 被调整为管理员的企业用户            | 短信   | 尊敬的【姓名】，【操作人】已将您调整为【企业名称】的管理员，请及时登录系统完成管理员认证，账号是您的手机号，请妥善保管     | 不含密码，需告知认证   |
| 4  | 外部机构用户新增               | 被添加的外部机构用户（不区分管理员/非管理员） | 短信   | 尊敬的【姓名】，【操作人】已将您添加为【外部机构名称】的用户，账号是您的手机号，密码:【密码】，请妥善保管           | 含密码，无需告知认证   |

| 变量       | 说明             |
| -------- | -------------- |
| 【姓名】     | 接收短信的用户姓名      |
| 【操作人】    | 执行添加/调整操作的人员姓名 |
| 【企业名称】   | 企业全称           |

| 【密码】     | 系统生成的初始密码      |

## 应收款及应付款到期提醒规则

### 需求概述

针对还款计划和付款计划，在约定还款日或约定付款日前向相关人员发送到期提醒，帮助业务人员提前关注应收款、应付款及对应的责任主体，降低逾期和漏付风险。

### 通知对象与渠道

| 业务类型 | 业务来源 | 接收对象               | 提醒节点      | 通知渠道  |
| ---- | ---- | ------------------ | --------- | ----- |
| 应收款  | 还款计划 | 对应项目的项目经理和公司财务所有人员 | 约定还款日前30天 | 通知    |
| 应收款  | 还款计划 | 对应项目的项目经理和公司财务所有人员 | 约定还款日前7天  | 通知、短信 |
| 应付款  | 付款计划 | 对应项目的项目经理和公司财务所有人员 | 约定付款日前30天 | 通知    |
| 应付款  | 付款计划 | 对应项目的项目经理和公司财务所有人员 | 约定付款日前7天  | 通知、短信 |

### 触发规则

1. 系统以还款计划的“约定还款日”作为应收款提醒基准日期，以付款计划的“约定付款日”作为应付款提醒基准日期。
2. 当系统日期等于基准日期前30个自然日时，发送一次通知提醒。
3. 当系统日期等于基准日期前7个自然日时，发送一次通知和短信提醒。
4. 同一业务明细、同一提醒节点仅发送一次，不因用户重复登录、列表刷新或任务重复执行而重复发送。
5. 约定还款日或约定付款日为空、已作废、已删除或已完成实际还款/实际付款的计划，不发送后续未触发的提醒。
6. 计划发生变更时，系统以变更后的约定日期重新计算提醒节点；已发送的历史通知保留，不重复补发已过期节点的提醒。
7. 触发日为非工作日时，仍按自然日计算并在该日期执行提醒，不顺延至工作日。

   <br />

### 应收款通知内容

#### 提前30天通知

**通知标题**：应收款到期提醒

**通知内容**：【公司名称】：项目【项目名称】，子项目【子项目名称】，还款计划编号【还款计划编号】，应收金额【应收金额】，实际还款方【实际还款方】，约定还款日为【约定还款日】，请提前关注还款情况。

#### 提前7天通知及短信

**通知标题**：应收款即将到期提醒

**通知内容**：【公司名称】：项目【项目名称】，子项目【子项目名称】，还款计划编号【还款计划编号】，应收金额【应收金额】，实际还款方【实际还款方】，约定还款日为【约定还款日】，请及时关注还款情况。

**短信内容**：【公司名称】应收款提醒：项目【项目名称】，子项目【子项目名称】，还款计划编号【还款计划编号】，应收金额【应收金额】，实际还款方【实际还款方】，约定还款日为【约定还款日】，请及时关注还款情况。

### 通知字段规则

| 字段     | 数据来源            | 展示规则                           |
| ------ | --------------- | ------------------------------ |
| 公司名称 | 还款计划或付款计划对应项目所属的公司主体 | 展示公司全称，放在通知及短信正文开头；应收款为本方收款公司，应付款为本方付款公司。 |
| 项目名称   | 还款计划或付款计划关联的项目  | 展示项目全称。                        |
| 子项目名称  | 还款计划或付款计划关联的子项目 | 展示子项目全称。                       |
| 还款计划编号 | 还款计划            | 仅应收款通知展示，展示还款计划编号。             |
| 付款计划编号 | 付款计划            | 仅应付款通知展示，展示付款计划编号。             |
| 应收金额   | 还款计划明细汇总金额      | 仅应收款通知展示，按当前还款计划应收金额展示，并带金额单位。 |
| 实际还款方  | 还款计划            | 仅应收款通知展示，展示还款计划配置的实际还款方。       |
| 应付金额   | 付款计划明细汇总金额      | 仅应付款通知展示，按当前付款计划应付金额展示，并带金额单位。 |
| 收款企业   | 付款计划            | 仅应付款通知展示，展示付款计划配置的收款企业。        |
| 约定还款日  | 还款计划            | 仅应收款通知展示，按“YYYY-MM-DD”格式展示。    |
| 约定付款日  | 付款计划            | 仅应付款通知展示，按“YYYY-MM-DD”格式展示。    |

### 异常与边界

1. 同一还款计划包含多条明细时，按还款计划编号合并发送一条提醒，并展示该计划的应收金额汇总；同一计划下实际还款方不同的，按实际还款方分别发送提醒。
2. 同一付款计划包含多条明细时，按付款计划编号合并发送一条提醒，并展示该计划的应付金额汇总；同一计划下收款企业不同的，按收款企业分别发送提醒。
3. 接收对象不存在、已停用或未维护手机号时，通知仍按可用渠道发送；短信因无有效手机号无法发送时，记录短信发送失败原因。
4. 金额、项目名称、子项目名称、计划编号或责任主体信息缺失时，不发送内容不完整的提醒，系统记录异常并提示业务人员补充计划信息。
5. 业务人员在提醒发送前完成实际还款或实际付款的，取消尚未发送的后续提醒。
