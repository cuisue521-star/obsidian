# 第 1 课：RAG 全链路与文档解析

> [!abstract] 本课定位
> 这是《RAG知识库》的样板课。课程采用“问题场景—核心知识—讲师演示—微练习—独立实训—评分—补救”的完整闭环，并直接启动阶段项目 **Obsidian 知识库助手**。

## 一、本节学习目标

完成本课后，你能够：

1. 能解释 RAG 的完整数据流及每一层的职责
2. 能判断哪些问题适合由知识库回答
3. 能解析 Markdown 标题、正文与 Wiki-link 并保留来源元数据
4. 能产出可供切分和检索使用的标准 Document 对象

## 二、学习路线

        ↓

        ↓

## 四、问题场景：为什么模型“知道很多”，却答不好你的内部资料

模型训练知识不等于你的本地笔记，更不等于最新、受控、可引用的业务资料。把整个 Vault 一次性放进上下文也不可持续：内容过多、成本高、重点被稀释，而且资料更新后难以增量处理。

RAG 的核心不是“加一个向量数据库”，而是建立证据链：

```text
用户问题 → 找到相关资料 → 把资料交给模型
        → 要求依据资料回答 → 返回可追溯引用
```

如果文档解析阶段就丢失路径、标题和层级，后面的检索和引用无法补救。

## 五、核心知识一：RAG 解决什么、不解决什么

### 5.1 RAG 为模型提供任务时证据

它让回答依据指定资料，而不是自动把模型永久训练成你的专家。

### 5.2 RAG 适合可检索、可引用的知识任务

制度问答、课程资料和项目文档适合；需要复杂实时交易或强权限操作时还需工具和业务系统。

### 5.3 没有证据时应拒答或请求补充

RAG 不能保证任何问题都有答案。正确拒答比编造更有价值。
## 六、核心知识二：RAG 的完整链路

### 6.1 离线链路负责准备资料

加载、清洗、切分、向量化和索引。

### 6.2 在线链路负责回答问题

查询理解、检索、重排、上下文组装、生成和引用。

### 6.3 评测贯穿两条链路

要分别判断“资料有没有找对”和“模型有没有依据资料回答”。
## 七、核心知识三：Document 对象与元数据

### 7.1 正文之外必须保留来源

至少保留相对路径、标题、标题层级、文档 ID 和更新时间。

### 7.2 相对路径适合 Obsidian 引用

可将来源转换为形如 `folder/note` 的 Wiki-link，既能追溯又能在 Vault 中打开。

### 7.3 元数据决定后续过滤和权限

目录、标签、文档类型和权限范围可以用于检索过滤。
## 八、核心知识四：Markdown 解析原则

### 8.1 标题表达语义边界

课程讲义应优先按标题层级组织，而非只按固定字符数切割。

### 8.2 不要破坏代码块、表格和 Wiki-link

清洗不是删除所有 Markdown；要保留影响语义和引用的信息。

### 8.3 原文与标准化文本分开保存

原文用于追溯，标准化文本用于检索，避免不可逆处理。

## 九、讲师演示：把 04 课程目录解析成可追溯 Document 列表

### 演示任务

扫描指定课程目录，只读取 Markdown，输出每篇文档的相对路径、标题和正文预览。
### 第一步：限定数据范围

使用目录白名单，忽略隐藏文件和非 Markdown 文件。
### 第二步：提取标题与正文

优先读取第一个一级标题；没有一级标题时使用文件名。
### 第三步：验证可追溯性

随机抽取一个 Document，确认可以从 source 找回原文件并生成 Wiki-link。

### 演示代码／结构示例

```python
from dataclasses import dataclass
from pathlib import Path


@dataclass
class Document:
    doc_id: str
    title: str
    source: str
    text: str


def read_markdown(path: Path, vault_root: Path) -> Document:
    text = path.read_text(encoding="utf-8")
    title = path.stem
    for line in text.splitlines():
        if line.startswith("# "):
            title = line[2:].strip()
            break

    relative = path.relative_to(vault_root).as_posix()
    return Document(
        doc_id=relative,
        title=title,
        source=relative,
        text=text,
    )


def load_documents(folder: Path, vault_root: Path) -> list[Document]:
    return [
        read_markdown(path, vault_root)
        for path in folder.rglob("*.md")
        if not any(part.startswith(".") for part in path.parts)
    ]
```

> [!warning] 演示要求
> 代码用于说明结构，不绑定某一厂商或框架版本。授课时要现场运行或使用等价模拟，展示正常结果、一个失败结果和验证过程。

## 十一、练习参考答案

### 练习 1 参考思路

课程讲义问答适合 RAG；实时余额应通过受权工具查询，RAG 不能保证实时和事务一致性。
### 练习 2 参考思路

无法引用、无法定位错误来源、无法增量更新或删除，也难以做权限过滤。
### 练习 3 参考思路

标题和标签可用于语义补充、过滤、展示和更精确的切分。

## 十二、独立实训：建立 Obsidian 知识库助手的文档入口

### 任务背景

本任务是 **Obsidian 知识库助手** 的第一个里程碑。成果将在后续课时继续扩展，不要把它当成一次性练习。

### 任务要求

1. 选择一个不含敏感信息的小目录
2. 扫描 Markdown 并生成文档清单
3. 为每篇文档保留相对路径、标题和原文
4. 忽略隐藏目录与非 Markdown 文件
5. 生成一份 JSONL 或可检查的解析结果
6. 抽查至少三篇文档的标题、路径和编码

### 提交物

1. 可运行代码、结构图或产品文档；
2. README 或复现说明；
3. 一次正常案例；
4. 一次边界或失败案例；
5. 修复前后的证据；
6. 不少于 150 字的项目复盘。

### 禁止事项

- 不允许一开始扫描整个 Vault
- 不允许丢弃来源路径
- 不允许把无法解析的文件静默忽略

## 十五、本课总结

本课需要带走以下五点：

1. RAG 的目标是为回答提供受控、可引用证据
2. 离线准备和在线问答是两条不同但关联的链路
3. Document 元数据决定引用、更新、过滤和评测能力
4. Markdown 标题和 Wiki-link 是 Obsidian 知识的重要结构
5. 本课先保证资料读得对，下一课才讨论怎样切分和检索

## 十六、课后复习卡片

### 问：为什么解析是 RAG 的基础？

答：后续切分和检索只能使用解析阶段留下的信息，丢失来源与结构后很难恢复。

### 问：RAG 有资料就一定能答对吗？

答：不一定，还取决于切分、召回、上下文组装、生成约束和评测。

### 问：为什么使用相对路径？

答：相对路径更便于迁移、生成 Obsidian Wiki-link，并避免绑定某台机器。
