# 第 4 章：RAG 知识库｜章节讲义

> [!abstract] 章节定位
> 让模型从“依赖训练知识回答”转向“依据你的资料回答”。本章以当前 Obsidian Vault 为真实数据源，强调引用、权限、更新和评测。

## 一、章节学习成果

完成本章后，学员能够：

1. 解析 Markdown 文档并保留可追溯元数据
2. 设计切分、向量化和检索流程
3. 生成带来源引用且有知识边界的回答
4. 用小型评测集分析召回与回答质量

## 二、前置能力

- 掌握模型 API、结构化输出和多轮会话
- 会读写文件并理解基础数据结构

### 前置诊断

- [ ] 能解释上一阶段项目的输入、处理、输出与验收方式；
- [ ] 能独立运行上一阶段成果；
- [ ] 能说出至少一个失败案例及修复方法；
- [ ] 不满足以上条件时，先走本章末尾的补课路径。

## 三、章节与项目的关系

```text
概念建立 → 讲师演示 → 微练习 → 项目里程碑
        → 故障注入 → 验收证据 → 复盘与迁移
```

本章不是学完所有概念后再做项目，而是每课都把一个可运行成果合并进 **Obsidian 知识库助手**。

## 四、贯穿项目：Obsidian 知识库助手

### 项目背景

构建一个只读取指定目录的 Obsidian 知识库助手。它能检索相关笔记、返回可点击的 Wiki-link 引用，并在证据不足时明确说不知道。

### 本章交付物

- 文档扫描与 Markdown 解析脚本
- 包含路径、标题、标题层级等元数据的切分结果
- 检索结果与引用展示
- 至少 15 条问题的评测集
- 对漏召回、错引用、答案越界的分析

### 建议目录

```text
Obsidian-知识库助手/
├── README.md          # 背景、运行方式、已知限制
├── src/               # 代码或主要实现
├── data/              # 脱敏样例与测试数据
├── tests/             # 自动或半自动测试
├── evidence/          # 截图、日志、评分与复盘
└── .env.example       # 配置示例，不放真实密钥
```

> [!warning] 安全要求
> 项目中的密钥、个人信息和企业敏感资料必须脱敏；涉及写入、发送、删除或外部调用的动作，要有权限边界、确认步骤和日志。

## 第 1 课：RAG 全链路与文档解析

### 学习目标

完成本课后，学员能够围绕以下内容进行解释、演示和独立实践：

- RAG 的问题边界
- 加载、清洗、切分、索引、检索、生成
- Markdown 标题和 Wiki-link
- 增量更新与重复文档

### 核心讲义

1. RAG 的问题边界
2. 加载、清洗、切分、索引、检索、生成
3. Markdown 标题和 Wiki-link
4. 增量更新与重复文档

> [!note] 讲解原则
> 先说明它解决什么问题，再说明关键机制，最后用项目中的真实输入和失败案例验证。不要把框架 API 的记忆当成掌握。

### 讲师演示

读取 04 课程目录，按标题层级解析正文并保留原始相对路径。

演示时必须同步展示：**输入、关键代码／配置、中间结果、最终结果、一个故障场景以及判断结果是否合格的方法**。

### 课堂微练习

1. 用自己的话解释本课最关键概念，禁止照抄定义；
2. 找出示例中的一个隐患，并说明它在真实项目中会造成什么后果；
3. 修改一个条件，观察输出或系统行为如何变化；
4. 将结果保存到阶段项目的 `evidence/` 或学习记录中。

### 项目里程碑

**限定一个小目录，产出文档清单和标准化 Document 对象。**

验收证据：

- 有可运行或可检查的成果；
- 有至少一个失败样例及修复记录；
- 能说明该成果如何服务阶段项目，而非孤立练习；
- 能在不复制原示例的情况下完成一个小变体。

## 六、阶段项目联调

### 联调任务

将四个课时产物合并为一个最小可用版本，并用一条真实任务走完整链路。联调记录至少包含：

1. 用户或调用方是谁，真实问题是什么；
2. 输入数据和预期输出；
3. 每个步骤的中间结果；
4. 一个主动制造的故障；
5. 系统如何发现、提示、恢复或安全终止；
6. 最终结果与验收标准的逐项对照；
7. 下一版本最值得优化的一件事。

### 最低验收标准

- [ ] 核心流程可独立运行或完整演示；
- [ ] README 足以让另一位学员理解并复现；
- [ ] 所有关键结论、操作或输出都有证据；
- [ ] 至少覆盖正常、边界、异常三类测试；
- [ ] 没有明文密钥和未脱敏敏感数据；
- [ ] 学员能现场完成一个小型变体任务。

### 项目答辩问题

1. 你的方案解决了什么真实问题？为什么不直接用一次普通对话完成？
2. 哪一部分是确定性程序，哪一部分交给模型？为什么？
3. 最容易失败的三个位置是什么？你如何发现它们？
4. 如果输入规模扩大十倍，当前方案首先会遇到什么问题？
5. 如果更换模型、数据或用户场景，哪些部分需要修改？

## 七、章节测评

| 维度 | 权重 | 合格证据 |
|---|---:|---|
| 概念理解 | 20% | 能用自己的话解释并比较方案 |
| 独立实现 | 25% | 不依赖逐行复制完成核心功能 |
| 项目整合 | 20% | 四课产物形成完整链路 |
| 异常与安全 | 15% | 有故障注入、边界与恢复记录 |
| 测试与证据 | 10% | 测试结果可复现、可追溯 |
| 表达与迁移 | 10% | 能答辩并完成小型变体 |

**通过标准：** 总分不低于 80 分，且“独立实现”“异常与安全”均不得低于该维度满分的 60%。

## 八、高频错误

- 切分后丢失文件路径，无法追溯答案来源
- 只看答案是否流畅，不检查检索证据
- Top-k 越大越好，导致噪声进入上下文
- 知识库没有答案时仍强制生成结论

## 九、不及格补课路径

1. 为每个 chunk 补齐 source、heading、chunk_id
2. 分别观察检索结果和最终回答
3. 加入“证据不足必须拒答”的专项测试

补课后不重复原题，使用相同能力、不同素材的变体任务重新验收。

## 十、AI 讲师授课提示

1. 先诊断再讲解；已经掌握的部分允许跳过，但项目验收不能跳过；
2. 学员第一次卡住时只指出方向，不直接给完整答案；
3. 第二次提供检查清单，第三次提供局部示例，最后才展示参考实现；
4. 每课结束前让学员解释“今天的产物怎样进入阶段项目”；
5. 对运行结果、来源、权限和成本保持证据意识；
6. 章节结束必须进行变体任务，防止把复制示例误判为掌握。

## 十一、章节总结

本章的学习完成标志不是“看完讲义”，而是：**能解释关键概念、完成项目里程碑、处理至少一个失败场景，并用可复现证据证明结果达标。**
