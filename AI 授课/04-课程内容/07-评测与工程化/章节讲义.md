# 第 7 章：评测与工程化｜章节讲义

> [!abstract] 章节定位
> 回答“它到底好不好、改完有没有变差、为什么失败”。评测必须成为开发循环的一部分，而不是上线前临时主观体验。

## 一、章节学习成果

完成本章后，学员能够：

1. 从真实需求构建有代表性的测试集
2. 组合规则、Rubric、模型评审与人工抽检
3. 记录轨迹、延迟、Token、成本和错误
4. 建立回归、安全与发布门禁

## 二、前置能力

- 已有可运行的 RAG 或 Agent 项目
- 理解日志、异常和基本测试思想

### 前置诊断

- [ ] 能解释上一阶段项目的输入、处理、输出与验收方式；
- [ ] 能独立运行上一阶段成果；
- [ ] 能说出至少一个失败案例及修复方法；
- [ ] 不满足以上条件时，先走本章末尾的补课路径。

## 三、章节与项目的关系

```text
概念建立 → 讲师演示 → 微练习 → 项目里程碑
        → 故障注入 → 验收证据 → 复盘与迁移
```

本章不是学完所有概念后再做项目，而是每课都把一个可运行成果合并进 **Agent 自动评测工具**。

## 四、贯穿项目：Agent 自动评测工具

### 项目背景

构建一个 Agent 自动评测工具：读取测试集，批量运行目标 Agent，依据规则与 Rubric 评分，汇总质量、延迟、成本和失败类型，并比较两个版本。

### 本章交付物

- 不少于 20 条的分层测试集
- 可复用的评分 Rubric
- 批量运行、记录和汇总脚本
- 版本对比与回归报告
- 安全、成本和稳定性门禁

### 建议目录

```text
Agent-自动评测工具/
├── README.md          # 背景、运行方式、已知限制
├── src/               # 代码或主要实现
├── data/              # 脱敏样例与测试数据
├── tests/             # 自动或半自动测试
├── evidence/          # 截图、日志、评分与复盘
└── .env.example       # 配置示例，不放真实密钥
```

> [!warning] 安全要求
> 项目中的密钥、个人信息和企业敏感资料必须脱敏；涉及写入、发送、删除或外部调用的动作，要有权限边界、确认步骤和日志。

## 第 1 课：测试集：从需求到能力证据

### 学习目标

完成本课后，学员能够围绕以下内容进行解释、演示和独立实践：

- 正常、边界、异常和对抗样例
- 输入、期望、证据与标签
- 真实分布与困难样例
- 数据版本和泄漏

### 核心讲义

1. 正常、边界、异常和对抗样例
2. 输入、期望、证据与标签
3. 真实分布与困难样例
4. 数据版本和泄漏

> [!note] 讲解原则
> 先说明它解决什么问题，再说明关键机制，最后用项目中的真实输入和失败案例验证。不要把框架 API 的记忆当成掌握。

### 讲师演示

从课程研发 Agent 的真实失败记录中抽取 5 类测试。

演示时必须同步展示：**输入、关键代码／配置、中间结果、最终结果、一个故障场景以及判断结果是否合格的方法**。

### 课堂微练习

1. 用自己的话解释本课最关键概念，禁止照抄定义；
2. 找出示例中的一个隐患，并说明它在真实项目中会造成什么后果；
3. 修改一个条件，观察输出或系统行为如何变化；
4. 将结果保存到阶段项目的 `evidence/` 或学习记录中。

### 项目里程碑

**建立 20 条测试集，标注能力项、风险级别和预期行为。**

验收证据：

- 有可运行或可检查的成果；
- 有至少一个失败样例及修复记录；
- 能说明该成果如何服务阶段项目，而非孤立练习；
- 能在不复制原示例的情况下完成一个小变体。

## 六、阶段项目联调

### 联调任务

将四个课时产物合并为一个最小可用版本，并用一条真实任务走完整链路。联调记录至少包含：

1. 用户或调用方是谁，真实问题是什么；
2. 输入数据和预期输出；
3. 每个步骤的中间结果；
4. 一个主动制造的故障；
5. 系统如何发现、提示、恢复或安全终止；
6. 最终结果与验收标准的逐项对照；
7. 下一版本最值得优化的一件事。

### 最低验收标准

- [ ] 核心流程可独立运行或完整演示；
- [ ] README 足以让另一位学员理解并复现；
- [ ] 所有关键结论、操作或输出都有证据；
- [ ] 至少覆盖正常、边界、异常三类测试；
- [ ] 没有明文密钥和未脱敏敏感数据；
- [ ] 学员能现场完成一个小型变体任务。

### 项目答辩问题

1. 你的方案解决了什么真实问题？为什么不直接用一次普通对话完成？
2. 哪一部分是确定性程序，哪一部分交给模型？为什么？
3. 最容易失败的三个位置是什么？你如何发现它们？
4. 如果输入规模扩大十倍，当前方案首先会遇到什么问题？
5. 如果更换模型、数据或用户场景，哪些部分需要修改？

## 七、章节测评

| 维度 | 权重 | 合格证据 |
|---|---:|---|
| 概念理解 | 20% | 能用自己的话解释并比较方案 |
| 独立实现 | 25% | 不依赖逐行复制完成核心功能 |
| 项目整合 | 20% | 四课产物形成完整链路 |
| 异常与安全 | 15% | 有故障注入、边界与恢复记录 |
| 测试与证据 | 10% | 测试结果可复现、可追溯 |
| 表达与迁移 | 10% | 能答辩并完成小型变体 |

**通过标准：** 总分不低于 80 分，且“独立实现”“异常与安全”均不得低于该维度满分的 60%。

## 八、高频错误

- 测试集只包含简单成功案例
- 只看平均分，掩盖高风险失败
- 让模型自己评自己且不校准
- 日志记录敏感原文或无法关联同一次运行

## 九、不及格补课路径

1. 增加边界、异常和对抗样例
2. 按风险和能力分桶观察结果
3. 随机抽检并计算人工与自动评分差异

补课后不重复原题，使用相同能力、不同素材的变体任务重新验收。

## 十、AI 讲师授课提示

1. 先诊断再讲解；已经掌握的部分允许跳过，但项目验收不能跳过；
2. 学员第一次卡住时只指出方向，不直接给完整答案；
3. 第二次提供检查清单，第三次提供局部示例，最后才展示参考实现；
4. 每课结束前让学员解释“今天的产物怎样进入阶段项目”；
5. 对运行结果、来源、权限和成本保持证据意识；
6. 章节结束必须进行变体任务，防止把复制示例误判为掌握。

## 十一、章节总结

本章的学习完成标志不是“看完讲义”，而是：**能解释关键概念、完成项目里程碑、处理至少一个失败场景，并用可复现证据证明结果达标。**
