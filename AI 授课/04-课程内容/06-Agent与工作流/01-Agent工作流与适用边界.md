# 第 1 课：Agent、工作流与适用边界

## 四、问题场景：为什么“让模型自己决定一切”通常不是最好的 Agent 设计

课程研发包含目标设计、提纲、讲义、练习、质检和修订。如果把一句“请自主完成整门课程”交给模型，可能快速得到内容，却难以回答：

- 当前执行到哪一步；
- 哪个输入产生了错误；
- 为什么跳过审核；
- 失败后从哪里恢复；
- 何时停止继续修改；
- 哪一版产物可以发布。

Agent 设计的关键不是最大化自主性，而是为任务选择恰当的自由度和控制结构。

## 五、核心知识一：四种常见实现形态

### 5.1 单次调用适合边界清楚的小任务

例如根据固定输入生成三条标题，不需要复杂状态。

### 5.2 工具链适合步骤固定的组合操作

例如搜索资料后读取并总结，程序可以明确规定顺序。

### 5.3 工作流适合有状态、分支和审核的过程

流程大体可知，但需要根据结果选择下一节点。

### 5.4 开放式 Agent 适合路径难以预先穷举的任务

模型可规划和选择动作，但必须受预算、工具、权限和终止条件约束。
## 六、核心知识二：自由度与可靠性的权衡

### 6.1 可预测任务优先确定性实现

能用普通代码、规则或固定 DAG 解决时，不必让模型反复决策。

### 6.2 模型用于语义判断和生成

例如评价提纲是否覆盖能力目标，或根据反馈修订内容。

### 6.3 关键动作保留人工审核

发布、覆盖文件和高成本执行不应只凭模型决定。
## 七、核心知识三：状态、节点与边

### 7.1 状态是流程共享的事实

课程主题、学员画像、当前提纲、审核意见和版本号应显式保存。

### 7.2 节点有明确输入输出契约

节点完成后应产生可检查的新状态，而不是只有一段聊天记录。

### 7.3 边表示确定顺序或条件路由

审核通过进入下一步，不通过返回修订，并设置最大修订次数。
## 八、核心知识四：终止、预算和恢复

### 8.1 完成条件必须可判断

例如必需资产齐全且质量分达到阈值。

### 8.2 预算限制防止无限循环

限制最大步骤、修订次数、时间或成本。

### 8.3 检查点让失败后继续

每个关键节点持久化状态，重试时避免重复有副作用的动作。

## 九、讲师演示：把“自动生成课程”改造成可控课程研发工作流

### 演示任务

输入课程主题与学员画像，依次生成学习目标、提纲和样课，并经过人工审核。
### 第一步：区分确定与生成步骤

文件命名、必填字段检查用代码；目标和内容草拟用模型；发布由人工确认。
### 第二步：画出状态图

定义 draft_goal、review_goal、draft_outline、review_outline、draft_lesson、quality_check、done。
### 第三步：加入失败边界

审核最多退回两次，超过后停止并输出需人工处理的原因。

### 演示代码／结构示例

```python
from dataclasses import dataclass, field


@dataclass
class CourseState:
    topic: str
    learner_profile: str
    objectives: list[str] = field(default_factory=list)
    outline: list[str] = field(default_factory=list)
    review_status: str = "pending"
    revision_count: int = 0
    current_step: str = "draft_objectives"


def route_after_review(state: CourseState) -> str:
    if state.review_status == "approved":
        return "draft_outline"
    if state.revision_count >= 2:
        return "needs_human_help"
    return "revise_objectives"


def is_finished(state: CourseState) -> bool:
    return state.current_step in {"done", "needs_human_help"}
```

> [!warning] 演示要求
> 代码用于说明结构，不绑定某一厂商或框架版本。授课时要现场运行或使用等价模拟，展示正常结果、一个失败结果和验证过程。

## 十一、练习参考答案

### 练习 1 参考思路

格式稳定可用普通代码或单次调用；检索问答是受控 RAG 链；课程研发适合带审核的工作流，局部可使用 Agent 决策。

## 十二、独立实训：设计课程研发 Agent 的可控工作流蓝图

### 任务背景

本任务是 **课程研发 Agent** 的第一个里程碑。成果将在后续课时继续扩展，不要把它当成一次性练习。

### 任务要求

1. 定义项目输入、最终交付物和非目标
2. 画出至少六个节点的流程图
3. 为每个节点写输入、输出和失败行为
4. 至少设计一个条件分支
5. 设置一个人工审核节点
6. 设置最大步骤和终止条件
7. 选择两个检查点并说明恢复策略

### 提交物

1. 可运行代码、结构图或产品文档；
2. README 或复现说明；
3. 一次正常案例；
4. 一次边界或失败案例；
5. 修复前后的证据；
6. 不少于 150 字的项目复盘。

### 禁止事项

- 不允许只画一条“模型→工具→结果”的模糊箭头
- 不允许所有节点都让模型自由选择
- 不允许没有失败和终止分支
- 不允许把聊天历史当成唯一状态存储

## 十五、本课总结

本课需要带走以下五点：

1. 实现形态应从最简单可靠的方案开始选择
2. 工作流擅长显式状态、分支、审核和恢复
3. 开放式 Agent 的自由度必须由 Harness 约束
4. 状态不是聊天记录，而是流程共享的结构化事实
5. 完成条件、预算和检查点决定系统能否安全运行

## 十六、课后复习卡片

### 问：什么时候不需要 Agent？

答：步骤和规则能够被普通代码或固定工作流可靠表达时。

### 问：工作流与 Agent 的差别是什么？

答：工作流路径更受预定义控制；Agent 在受限环境中拥有更大的规划和动作选择空间。

### 问：为什么人工审核也是系统能力？

答：它把高风险或主观决策放到合适责任主体，并为自动化提供明确边界。

## 十七、AI 讲师授课提示

> 本部分供授课 Agent 使用，不要求学员背诵。

### 授课节奏

1. 先进行前置检查，并记录学员原始解释；
2. 从问题场景进入，不要先堆叠术语；
3. 每个核心知识点都回到 **课程研发 Agent** 的真实决策；
4. 演示时展示输入、中间过程、输出、失败和验收；
5. 学员第一次失败只给方向，第二次给检查清单，第三次给局部示例；
6. 只有提交独立版本后才开放参考答案；
7. 结束前要求学员现场完成一个素材或条件变化的小变体；
8. 把本课产物、得分、错误类型和补课结果写入学习档案。

### 讲师判定“已掌握”的证据

- 能不照抄定义解释本课核心机制；
- 能指出方案边界和至少一个高风险失败点；
- 能独立完成项目首个里程碑；
- 能提供正常、边界或失败案例的可复现证据；
- 能解释下一课将在当前成果上增加什么能力。
