# 第 1 章：AI 与大模型基础｜章节讲义

> [!abstract] 章节定位
> 建立正确的 AI 使用观。重点不是背诵术语，而是学会判断任务风险、提供上下文、设计验收标准，并形成“生成结果必须被检查”的习惯。


## 一、章节学习成果

完成本章后，学员能够：

1. 解释大模型、上下文、Token、幻觉与能力边界
2. 把模糊需求改写为可执行、可验收的 Prompt
3. 根据输出问题进行有依据的迭代
4. 将复杂任务拆成可观察的步骤

## 二、前置能力

- 会使用至少一种 AI 对话工具
- 能描述一个真实的学习或工作任务

### 前置诊断

- [ ] 能解释上一阶段项目的输入、处理、输出与验收方式；
- [ ] 能独立运行上一阶段成果；
- [ ] 能说出至少一个失败案例及修复方法；
- [ ] 不满足以上条件时，先走本章末尾的补课路径。

## 三、章节与项目的关系

```text
概念建立 → 讲师演示 → 微练习 → 项目里程碑
        → 故障注入 → 验收证据 → 复盘与迁移
```

本章不是学完所有概念后再做项目，而是每课都把一个可运行成果合并进 **Prompt 工作台**。

## 四、贯穿项目：Prompt 工作台

### 项目背景

很多人保存了大量 Prompt，却无法知道哪个版本更好。你将制作一个可记录任务、Prompt 版本、模型输出、问题标签和评分结果的工作台。第一阶段可以先用 Markdown 或表格完成，不要求开发界面。

### 本章交付物

- 一份包含目标、背景、约束、输出格式和验收标准的 Prompt 卡片
- 至少 3 个 Prompt 版本及迭代原因
- 同一测试任务的输出对比记录
- 基于 Rubric 的人工评分和最终结论

### 建议目录

```text
Prompt-工作台/
├── README.md          # 背景、运行方式、已知限制
├── src/               # 代码或主要实现
├── data/              # 脱敏样例与测试数据
├── tests/             # 自动或半自动测试
├── evidence/          # 截图、日志、评分与复盘
└── .env.example       # 配置示例，不放真实密钥
```

> [!warning] 安全要求
> 项目中的密钥、个人信息和企业敏感资料必须脱敏；涉及写入、发送、删除或外部调用的动作，要有权限边界、确认步骤和日志。

## 第 1 课：大模型是什么，以及如何正确使用

### 学习目标

完成本课后，学员能够围绕以下内容进行解释、演示和独立实践：

- 大模型的生成机制与概率性
- Token、上下文和幻觉
- 适合与不适合交给模型的任务
- 五要素 Prompt 任务说明书

### 核心讲义

1. 大模型的生成机制与概率性
2. Token、上下文和幻觉
3. 适合与不适合交给模型的任务
4. 五要素 Prompt 任务说明书

> [!note] 讲解原则
> 先说明它解决什么问题，再说明关键机制，最后用项目中的真实输入和失败案例验证。不要把框架 API 的记忆当成掌握。

### 讲师演示

把“帮我做一份学习计划”改造成有对象、周期、约束和验收条件的任务说明。

演示时必须同步展示：**输入、关键代码／配置、中间结果、最终结果、一个故障场景以及判断结果是否合格的方法**。

### 课堂微练习

1. 用自己的话解释本课最关键概念，禁止照抄定义；
2. 找出示例中的一个隐患，并说明它在真实项目中会造成什么后果；
3. 修改一个条件，观察输出或系统行为如何变化；
4. 将结果保存到阶段项目的 `evidence/` 或学习记录中。

### 项目里程碑

**选取一个真实任务，记录原始 Prompt、首次输出、问题与改进版。**

验收证据：

- 有可运行或可检查的成果；
- 有至少一个失败样例及修复记录；
- 能说明该成果如何服务阶段项目，而非孤立练习；
- 能在不复制原示例的情况下完成一个小变体。

## 六、阶段项目联调

### 联调任务

将四个课时产物合并为一个最小可用版本，并用一条真实任务走完整链路。联调记录至少包含：

1. 用户或调用方是谁，真实问题是什么；
2. 输入数据和预期输出；
3. 每个步骤的中间结果；
4. 一个主动制造的故障；
5. 系统如何发现、提示、恢复或安全终止；
6. 最终结果与验收标准的逐项对照；
7. 下一版本最值得优化的一件事。

### 最低验收标准

- [ ] 核心流程可独立运行或完整演示；
- [ ] README 足以让另一位学员理解并复现；
- [ ] 所有关键结论、操作或输出都有证据；
- [ ] 至少覆盖正常、边界、异常三类测试；
- [ ] 没有明文密钥和未脱敏敏感数据；
- [ ] 学员能现场完成一个小型变体任务。

### 项目答辩问题

1. 你的方案解决了什么真实问题？为什么不直接用一次普通对话完成？
2. 哪一部分是确定性程序，哪一部分交给模型？为什么？
3. 最容易失败的三个位置是什么？你如何发现它们？
4. 如果输入规模扩大十倍，当前方案首先会遇到什么问题？
5. 如果更换模型、数据或用户场景，哪些部分需要修改？

## 七、章节测评

| 维度 | 权重 | 合格证据 |
|---|---:|---|
| 概念理解 | 20% | 能用自己的话解释并比较方案 |
| 独立实现 | 25% | 不依赖逐行复制完成核心功能 |
| 项目整合 | 20% | 四课产物形成完整链路 |
| 异常与安全 | 15% | 有故障注入、边界与恢复记录 |
| 测试与证据 | 10% | 测试结果可复现、可追溯 |
| 表达与迁移 | 10% | 能答辩并完成小型变体 |

**通过标准：** 总分不低于 80 分，且“独立实现”“异常与安全”均不得低于该维度满分的 60%。

## 八、高频错误

- 把 Prompt 当成万能咒语，忽略输入资料质量
- 只展示最好的一次输出，隐藏失败过程
- 要求“准确、专业”，却不给验收标准
- 把语言流畅等同于事实正确

## 九、不及格补课路径

1. 重新完成一个“低风险生成任务”和一个“高风险事实任务”的对比实验
2. 使用固定 Rubric 对三个 Prompt 版本盲评
3. 口头解释每次修改解决了什么具体问题

补课后不重复原题，使用相同能力、不同素材的变体任务重新验收。

## 十、AI 讲师授课提示

1. 先诊断再讲解；已经掌握的部分允许跳过，但项目验收不能跳过；
2. 学员第一次卡住时只指出方向，不直接给完整答案；
3. 第二次提供检查清单，第三次提供局部示例，最后才展示参考实现；
4. 每课结束前让学员解释“今天的产物怎样进入阶段项目”；
5. 对运行结果、来源、权限和成本保持证据意识；
6. 章节结束必须进行变体任务，防止把复制示例误判为掌握。

## 十一、章节总结

本章的学习完成标志不是“看完讲义”，而是：**能解释关键概念、完成项目里程碑、处理至少一个失败场景，并用可复现证据证明结果达标。**
