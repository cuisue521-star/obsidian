# 第 1 课：大模型是什么，以及如何正确使用

> [!abstract] 本课定位
> 这是《AI 与大模型基础》的第 1 节课。我们不从复杂原理开始，而是先建立一套能直接用于工作和学习的判断框架：**大模型是什么、它擅长什么、它为什么会出错，以及我们应该如何向它提要求。**

## 一、本节学习目标

完成本课后，你能够：

1. 用自己的话解释“大模型”是什么，而不是只会背定义；
2. 区分模型的“生成能力”和“事实可靠性”；
3. 解释 Token、上下文和幻觉这三个基础概念；
4. 判断一个任务适不适合交给大模型；
5. 使用“角色—任务—背景—约束—输出格式”写出一版可执行的 Prompt；
6. 通过一个小练习证明自己不是只会复制模板。

## 二、学习路线

```text
你现在在哪里？
        ↓
大模型是什么？
        ↓
它为什么能生成内容？
        ↓
它擅长什么、不擅长什么？
        ↓
为什么会出现幻觉？
        ↓
怎样把任务交给它？
        ↓
独立完成一个 Prompt 任务
```

- E. 还没有形成固定场景

### 题目 2

- C. 大模型知道互联网上所有信息，所以不会犯错；

### 题目 3

## 四、问题场景：为什么 AI 有时很聪明，有时又很不可靠？

假设你让 AI 完成下面四个任务：

| 任务 | 可能表现 | 初步判断 |
|---|---|---|
| 将一段会议纪要整理成行动项 | 通常效果较好 | 信息重组与表达 |
| 根据公司制度生成流程清单 | 取决于是否提供了制度原文 | 需要限定资料来源 |
| 解释一段报错代码 | 通常有帮助，但需要运行验证 | 分析与排错 |
| 告诉你今天某产品的准确价格 | 可能过时或编造 | 需要实时来源核验 |

这里出现了一个核心矛盾：

> **大模型很擅长组织语言，不等于它永远掌握事实。**

所以，学习 AI 的第一原则不是“相信 AI”，也不是“怀疑 AI”，而是：

> **根据任务风险，决定需要多少验证。**

## 五、核心知识一：大模型到底是什么

### 5.1 先用一句话理解

大模型可以理解为一种经过大量数据训练、能够根据上下文生成和处理语言、代码及其他内容的模型。

更直白地说：

> 你给它一段输入，它会根据已经学到的模式和当前上下文，预测接下来什么内容最合适。

这里的“预测”不是简单随机猜词，而是综合了：

- 输入中的任务要求；
- 已经提供的背景资料；
- 对话历史；
- 模型在训练中学到的语言、代码和知识模式；
- 你要求的语气、格式和限制条件。

### 5.2 它不是搜索引擎，也不是数据库

大模型和搜索引擎的工作方式不同：

| 对比项 | 搜索引擎 | 大模型 |
|---|---|---|
| 主要动作 | 找到并排序已有页面 | 根据上下文生成内容 |
| 输出来源 | 通常可以打开原始网页 | 不一定自动提供来源 |
| 优势 | 查找最新事实 | 总结、改写、推理、生成 |
| 主要风险 | 结果质量参差 | 可能生成看似合理但不准确的内容 |
| 使用方式 | 适合核实信息 | 适合处理任务和组织信息 |

在真实工作中，二者经常组合使用：

```text
搜索／知识库提供资料
        ↓
大模型理解、整理、转换和生成
        ↓
人类检查关键事实与结果
```

### 5.3 “大”体现在哪里

“大”通常体现在模型规模和训练能力上，但初学阶段不需要记住具体参数数量。你只要理解：

- 训练数据更丰富，可能覆盖更多语言、代码和任务模式；
- 模型能力更强，能够处理更复杂的上下文和任务；
- 能力更强不代表不会出错；
- 不同模型的速度、成本、上下文长度和擅长领域不同。

## 六、核心知识二：三个必须掌握的概念

### 6.1 Token：模型处理文本的基本单位

模型通常不会像人一样直接按“字”或“词”理解文本，而是把文本切分成一段段 Token，再进行处理。

你可以先把 Token 理解成：

> **模型计算文本时使用的基本片段。**

Token 会影响：

- 一次能处理多少内容；
- 输入和输出的成本；
- 长文档是否需要切分；
- 对话历史能保留多少。

不必把 Token 简单等同于汉字、单词或字符。不同语言、符号和代码的切分方式可能不同。

### 6.2 上下文：模型当前能看到的工作范围

上下文包括模型在当前任务中能够使用的信息，例如：

- 当前问题；
- System Prompt；
- 历史对话；
- 你粘贴的资料；
- 工具返回的结果；
- 任务约束和输出格式。

上下文不是永久记忆。一个对话结束后，模型是否还能继续使用相关信息，取决于具体产品的记忆机制和你是否再次提供资料。

**实用判断：**

如果 AI 的回答越来越偏题，常见原因之一是：

- 任务说明不清楚；
- 关键资料没有放进上下文；
- 上下文太长，重点被淹没；
- 对话中混入了相互冲突的要求。

### 6.3 幻觉：看起来合理但没有可靠依据

幻觉不是 AI “故意撒谎”，而是模型可能在缺少足够依据时，仍然生成一段语言上连贯的内容。

典型表现：

- 捏造不存在的论文、法规、产品或链接；
- 把不确定内容说得非常肯定；
- 混淆不同人物、时间、版本或概念；
- 代码看起来正确，但实际无法运行；
- 用一个似是而非的答案填补信息空白。

降低幻觉的基本方法：

1. 给出可靠的原始资料；
2. 要求区分“资料明确说明”和“推测”；
3. 要求引用依据或标注无法确认的地方；
4. 对高风险信息进行外部核验；
5. 用测试、运行和实际结果验证代码与方案。

> [!warning] 重要边界
> 对医疗、法律、财务、安全、生产环境操作等高风险任务，AI 输出只能作为辅助信息，不能替代专业审核和正式依据。

## 七、核心知识三：大模型擅长什么，不擅长什么

### 7.1 更适合交给大模型的任务

这些任务通常具有“输入明确、输出可检查、风险可控”的特点：

- 总结、提炼和改写已有资料；
- 按指定格式整理信息；
- 生成多个方案供人比较；
- 将自然语言转换成表格、清单或 JSON；
- 解释代码、报错和概念；
- 生成初稿、测试用例和练习题；
- 进行角色扮演和模拟对话；
- 根据明确标准进行初步分类或检查。

### 7.2 需要谨慎交给大模型的任务

- 要求最新价格、政策、版本或实时数据；
- 需要百分之百准确的事实判断；
- 直接执行删除、转账、发布、审批等不可逆操作；
- 涉及个人隐私、商业秘密或敏感数据；
- 只给出一句模糊要求，却希望得到完整可靠方案；
- 需要真实运行但没有测试环境的代码。

### 7.3 任务风险四象限

|  | 低风险 | 高风险 |
|---|---|---|
| **结果容易检查** | 可以让 AI 先做初稿 | AI 先做，人类逐项审核 |
| **结果难以检查** | 先要求说明依据和不确定性 | 不应直接依赖 AI，必须引入专家或正式流程 |

## 八、核心知识四：Prompt 不是咒语，而是任务说明书

一个好 Prompt 的作用不是“把 AI 哄得更聪明”，而是减少任务歧义，让模型知道：

- 你希望它扮演什么角色；
- 要完成什么任务；
- 应该使用哪些背景资料；
- 有什么限制条件；
- 最终输出成什么样子。

### 8.1 五要素 Prompt 结构

```text
角色（Role）
+ 任务（Task）
+ 背景（Context）
+ 约束（Constraints）
+ 输出格式（Output Format）
```

### 8.2 一个模糊的 Prompt

```text
帮我做一个 AI 学习计划。
```

问题在于：

- 不知道学习者是谁；
- 不知道最终目标；
- 不知道基础水平；
- 不知道可投入时间；
- 不知道输出形式；
- 不知道如何判断计划是否合理。

### 8.3 改进后的 Prompt

```text
你是一名面向职场人的 AI 学习教练。

请为我设计一份 4 周的 AI Agent 入门学习计划。

我的情况：
- 有测试工作经验；
- Python 基础较弱，但能阅读简单代码；
- 每天可学习 1.5 小时；
- 希望最终做出一个能读取 Markdown 文档并回答问题的知识库助手。

要求：
1. 按周拆分学习目标；
2. 每周安排 5 天任务，每天不超过 90 分钟；
3. 每天都包含“学习内容”和“动手练习”；
4. 标出每项任务的前置知识；
5. 最后一周安排一个可验收的项目；
6. 如果某项内容超出入门阶段，请明确标注“可选”。

请用 Markdown 表格输出，列出：周次、目标、每日任务、练习成果、验收标准。
```

### 8.4 为什么改进后更好

不是因为字数更长，而是因为它补齐了任务所需的信息：

- 角色明确；
- 目标明确；
- 学员背景明确；
- 时间约束明确；
- 结果形式明确；
- 评价方式明确。

## 九、讲师演示：把一个模糊需求变成可执行任务

### 演示任务

> “帮我写一份项目复盘。”

### 第一步：识别缺失信息

讲师向学员提问：

1. 复盘的对象是什么项目？
2. 读者是谁？
3. 复盘的目的是什么？
4. 需要覆盖哪些维度？
5. 有没有事实资料或会议纪要？
6. 输出格式和长度有什么要求？

### 第二步：补齐任务说明

```text
你是一名项目复盘教练。

请根据我提供的项目资料，整理一份面向项目组成员的复盘初稿。

目标：找出项目中可复用的做法、实际问题和下一步改进措施。

要求：
- 只使用我提供的资料，不补写未经证实的事实；
- 将“事实”“推测”“待确认事项”分开；
- 不进行责任归因，不使用情绪化表达；
- 输出结构为：项目目标、结果概览、做得好的地方、问题与影响、根因假设、改进措施、待确认问题；
- 对每条改进措施写出负责人、截止时间和验收标准；
- 如果资料不足，先列出需要我补充的信息。
```

### 第三步：验证输出

不能只看 AI 写得是否流畅，还要检查：

- 有没有编造事实；
- 有没有把推测写成结论；
- 有没有遗漏关键问题；
- 改进措施能否执行；
- 负责人、时间和验收标准是否具体。

## 十、课堂微练习

### 练习 1：判断任务风险

请为下面任务标注：

- `A`：适合让 AI 先做初稿；
- `B`：可以使用，但必须提供资料并核验；
- `C`：不应直接依赖 AI。

1. 把一页会议记录整理成待办清单；
2. 根据未知来源的回答判断合同是否可以签署；
3. 将一份公司内部制度改写成新员工易懂版本；
4. 让 AI 直接删除生产数据库中的数据；
5. 根据官方 API 文档生成一个调用示例；
6. 让 AI 告诉你某个最新软件版本的全部变化，但没有提供来源。

### 练习 2：找出 Prompt 缺陷

下面这个 Prompt 至少有四个问题，请写出来：

```text
你是专家，帮我做一个很好的 AI 课程，要详细、专业、实用，最好能让我学会 Agent。
```

### 练习 3：独立改写

请选择一个你近期真实想完成的任务，按照下面的结构写出 Prompt：

```text
角色：
任务：
背景：
约束：
输出格式：
验收标准：
```

> [!note] 课堂要求
> 这道题不追求 Prompt 写得“像模板”，而是要求别人拿到你的 Prompt 后，能够明确知道要完成什么。

## 十一、练习参考答案

### 练习 1参考答案

1. A：结果容易检查，适合先让 AI 整理；
2. B／C：涉及合同判断和法律风险，必须由专业人员依据正式材料审核；
3. B：应提供制度原文，并检查是否改变原意；
4. C：不可逆、高风险生产操作，不能让 AI 直接执行；
5. B：需要以官方文档为依据，并运行验证示例；
6. B：需要先获取并核验最新官方发布信息，不能依赖模型记忆。

### 练习 2参考答案

至少包括：

- “专家”范围不明确；
- “很好、详细、专业、实用”不可测量；
- 没有说明学员是谁；
- 没有说明学习周期和时间；
- 没有明确 Agent 的学习范围；
- 没有说明最终项目；
- 没有规定课程形式；
- 没有验收标准；
- 没有要求区分必学与选学内容。

参考改写：

```text
你是一名面向测试工程师的 AI Agent 学习教练。
请为一名 Python 基础较弱、每天可学习 1 小时的学员设计 4 周入门路线。
目标是完成一个能读取 Markdown 文档并回答问题的知识库助手。
每周安排 5 天任务，每天包含学习内容、动手练习和可提交成果。
请标出前置知识、预计时长和验收标准；信息不足时先提出问题，不要自行假设。
用 Markdown 表格输出。
```

## 十二、独立实训：制作你的第一份 AI 任务说明书

### 任务名称

**Prompt 工作台：把一个真实任务交给 AI**

### 任务要求

选择一个真实任务，例如：

- 整理一份工作记录；
- 设计一个学习计划；
- 分析一段报错；
- 生成测试用例；
- 将一段制度改写成流程；
- 为一个想法设计 Agent 方案。

提交以下内容：

1. 原始的模糊需求；
2. 补充后的结构化 Prompt；
3. AI 的第一次输出；
4. 你发现的问题；
5. 修改后的第二版 Prompt；
6. 前后两次输出的对比；
7. 你对“大模型能力边界”的判断。

### 禁止事项

- 不要只提交网上复制的 Prompt；
- 不要只展示最终答案；
- 不要把 AI 的输出直接当成事实证明；
- 不要为了让结果好看而隐藏失败过程。

## 十三、评分规则

总分 100 分。

| 评分维度 | 分值 | 合格表现 |
|---|---:|---|
| 任务目标 | 15 | 能说明真实任务和预期结果 |
| 背景信息 | 15 | 提供了影响结果的必要背景 |
| 约束条件 | 15 | 明确范围、限制和风险边界 |
| 输出格式 | 10 | 输出结构可执行、可检查 |
| 验收标准 | 15 | 能判断结果是否达标 |
| 迭代过程 | 15 | 展示了失败、分析和改进 |
| 事实意识 | 10 | 能区分生成内容与待核实事实 |
| 表达清晰度 | 5 | 结构清楚、没有明显歧义 |

### 通过标准

- 80 分及以上：进入下一课；
- 60～79 分：完成补救任务后重交；
- 60 分以下：重新学习“任务说明书”和“幻觉风险”部分。

## 十四、常见错误与补救

### 错误 1：只写“你是专家”

**问题：** 角色没有对应任务场景，无法帮助模型确定工作方式。

**补救：** 写清楚服务对象、任务类型和专业边界。

### 错误 2：堆砌“详细、专业、全面”

**问题：** 这些词没有可执行标准。

**补救：** 换成数量、结构、范围、格式和验收条件。

### 错误 3：不给背景资料，却要求准确结论

**问题：** 模型可能用一般性知识补空白，造成幻觉。

**补救：** 提供原文，或要求 AI 先列出待确认信息。

### 错误 4：第一次输出不满意就认为模型不行

**问题：** 可能是任务信息不足，而不是模型完全不能完成。

**补救：** 对输出进行诊断，补充最影响结果的缺失信息。

### 错误 5：AI 说“已经完成”就认为真的完成

**问题：** 语言上的完成不等于任务结果合格。

**补救：** 使用验收标准、运行测试、事实核验或人工检查。

## 十五、本课总结

今天最重要的不是背下“大模型”的定义，而是掌握下面五句话：

1. 大模型是根据上下文生成内容的模型，不天然保证事实正确；
2. 它擅长处理和生成内容，但不等于拥有实时、完整、可靠的事实数据库；
3. Token 决定文本如何被模型处理，上下文决定模型当前能看到什么；
4. 幻觉意味着“表达得像真的”不等于“事实就是真的”；
5. 好 Prompt 的本质是把任务目标、背景、约束、格式和验收标准说清楚。

## 十六、课后复习卡片

### 问：大模型最适合做什么？

答：对已有信息进行总结、转换、生成和初步分析，尤其是结果容易检查、风险可控的任务。

### 问：为什么模型会出现幻觉？

答：在缺少足够依据时，模型仍可能根据语言模式生成连贯内容，因此需要资料、来源和验证。

### 问：Prompt 越长越好吗？

答：不是。关键是信息相关、结构清楚、要求可执行。无关内容越多，反而可能干扰模型。

### 问：怎样判断自己真的学会了？

答：不看是否听懂解释，而看能否独立完成一个新任务，并说明自己的设计和验证过程。

## 十七、AI 讲师授课提示

> 本部分供授课 Agent 使用，不是给学员背诵的内容。

### 授课节奏

1. 先让学员回答前置检查；
2. 根据回答决定是否补充“搜索引擎与大模型”的区别；
3. 讲解 Token、上下文、幻觉时各举一个生活或工作例子；
4. 讲 Prompt 五要素后，不直接要求背模板，先让学员改写模糊需求；
5. 练习 3 必须使用学员自己的真实任务；
6. 如果学员直接索要参考答案，先追问其任务背景和验收标准；
7. 只有学员提交自己的版本后，才提供分级提示；
8. 课程结束前必须让学员口头解释：为什么自己的 Prompt 比原版本更好。

### 讲师判定“已掌握”的证据

- 能自己解释大模型与搜索引擎的差异；
- 能指出一个任务的主要风险；
- 能独立写出结构化 Prompt；
- 能根据第一次输出发现具体问题；
- 能完成一次有理由的 Prompt 迭代。
