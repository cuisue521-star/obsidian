# 第 1 课：Python 最小语法与函数化思维

> [!abstract] 本课定位
> 这是《Python与API基础》的样板课。课程采用“问题场景—核心知识—讲师演示—微练习—独立实训—评分—补救”的完整闭环，并直接启动阶段项目 **命令行 AI 助手**。

## 一、本节学习目标

完成本课后，你能够：

1. 能解释变量、列表、字典、条件、循环和函数在 AI 应用中的作用

3. 能建立可运行的命令行 AI 助手项目骨架
4. 能通过打印、返回值和小步运行定位基础错误

## 四、问题场景：为什么“能运行”还不等于“会编程”

假设你复制了一段能够接收问题并输出答案的 Python 代码。第一次运行成功，但当你想增加“保存历史”“切换 Prompt”“处理空输入”时，代码迅速变得混乱。

问题通常不在于少记了一个语法，而在于没有形成下面的程序思维：

```text
输入是什么？
    ↓
数据以什么结构保存？
    ↓
经过哪些处理步骤？
    ↓
每一步由哪个函数负责？
    ↓
怎样判断输出正确？
```

因此，本课只学习进入 AI 应用开发所需的最小语法，并立即把它们组织进真实项目。

## 五、核心知识一：变量与数据结构是“给信息起名字”

### 5.1 变量不是盒子口诀，而是可读的业务命名

变量让程序中的值具有含义。`user_question` 比 `x` 更能说明数据用途。命名应表达“这是什么”，而不是“它排第几个”。

### 5.2 列表用于有顺序的一组内容

对话消息、任务步骤和测试样例通常适合列表。列表允许按顺序读取、追加和遍历。

### 5.3 字典用于描述一个对象

一条消息可以包含 `role` 和 `content`，一个任务可以包含 `title`、`steps` 和 `risk`。字典让相关字段组织在一起。
## 六、核心知识二：条件与循环控制程序路径

### 6.1 条件判断让程序处理不同情况

程序不能只处理“用户输入永远正确”的理想情况。空输入、退出命令和非法选项都需要分支。

### 6.2 循环让一次性脚本成为可持续交互

命令行助手需要不断接收问题，直到用户输入退出命令。循环必须有明确终止条件，避免无法退出。

### 6.3 先处理边界，再进入核心逻辑

先判断是否为空、是否退出，再调用处理函数，可以让主流程更清楚。
## 七、核心知识三：函数化思维

### 7.1 一个函数只负责一件可以说清楚的事

例如 `get_user_input()` 负责读取，`build_prompt()` 负责组装，`show_result()` 负责展示。

### 7.2 参数是函数所需输入，返回值是可复用结果

相比依赖随处可见的全局变量，明确参数与返回值更容易测试和修改。

### 7.3 主流程应该像目录一样可读

看到 `main()` 就能理解程序先做什么、后做什么，而不用立即钻进实现细节。
## 八、核心知识四：最小可运行项目结构

### 8.1 先做骨架，再接模型 API

本课暂时用本地函数模拟模型回答，确保输入、处理、输出链路正确。

### 8.2 把变化隔离在函数内部

以后替换真实模型调用时，只需修改客户端函数，不应重写整个命令行交互。

### 8.3 每次只增加一个能力并立即验证

先回显，再生成模拟结果，再处理退出和空输入。小步运行比一次写完更容易定位错误。

## 九、讲师演示：把一段顺序脚本改造成命令行助手骨架

### 演示任务

构建一个“任务分析助手”：用户输入一个任务，程序输出任务名称、建议步骤和风险提示。本课不调用真实模型。
### 第一步：写出最小数据流

先明确：用户文本进入 `analyze_task()`，返回字典，再由 `show_result()` 展示。
### 第二步：拆分函数

使用 `get_user_input()`、`analyze_task()`、`show_result()` 和 `main()`，让每个函数职责可单独解释。
### 第三步：处理边界

加入空输入和 `exit` 判断，并演示错误缩进、键名拼错时如何根据报错定位。

### 演示代码／结构示例

```python
def get_user_input() -> str:
    return input("请输入任务，输入 exit 退出：").strip()


def analyze_task(task: str) -> dict:
    return {
        "title": task,
        "steps": ["澄清目标", "准备输入", "执行并检查结果"],
        "risk": "当前为规则模拟结果，尚未调用模型",
    }


def show_result(result: dict) -> None:
    print(f"\n任务：{result['title']}")
    for index, step in enumerate(result["steps"], start=1):
        print(f"{index}. {step}")
    print(f"风险：{result['risk']}\n")


def main() -> None:
    while True:
        task = get_user_input()
        if task.lower() == "exit":
            break
        if not task:
            print("任务不能为空。")
            continue
        show_result(analyze_task(task))


if __name__ == "__main__":
    main()
```

> [!warning] 演示要求
> 代码用于说明结构，不绑定某一厂商或框架版本。授课时要现场运行或使用等价模拟，展示正常结果、一个失败结果和验证过程。

## 十五、本课总结

本课需要带走以下五点：

1. 语法是表达程序意图的工具，不是学习终点
2. 列表描述有顺序的一组内容，字典描述带字段的对象
3. 条件和循环让程序能够处理分支与持续交互
4. 函数应有清晰输入、单一职责和可复用返回值
5. 先搭建稳定骨架，再把模拟处理替换为模型 API

## 十六、课后复习卡片

### 问：为什么要先用模拟函数，而不是马上接模型？

答：先验证程序自身的数据流和职责边界，避免把基础代码问题与网络、鉴权或模型问题混在一起。

### 问：函数越多越好吗？

答：不是。函数应围绕清晰职责和变化边界拆分，过度拆分也会增加理解成本。

### 问：怎样证明不是只会复制？

答：在不看示例的情况下增加新命令、处理新边界，并解释修改位置和原因。
