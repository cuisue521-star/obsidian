# 第 1 课：Function Calling：从意图到工具契约

> [!abstract] 本课定位
> 这是《工具调用与MCP》的样板课。课程采用“问题场景—核心知识—讲师演示—微练习—独立实训—评分—补救”的完整闭环，并直接启动阶段项目 **多工具工作助手**。

## 一、本节学习目标

完成本课后，你能够：

1. 能解释模型建议调用与程序实际执行之间的边界
2. 能设计职责单一、参数明确、结果可校验的工具契约
3. 能对工具参数做业务校验与权限检查
4. 能记录一次完整的工具请求、执行与结果回传链路

## 四、问题场景：为什么模型会“说要做”，却没有真正完成动作

语言模型本身生成的是内容。即使它输出“我已经读取文件”，也不代表文件真的被读取。工具调用把生成式决策与确定性程序连接起来：模型提出工具名称和参数，应用程序验证后执行真实函数，再把结果交还模型组织回答。

关键边界是：

> **模型可以提出动作，但程序拥有最终执行权。**

如果工具契约含糊、权限过大或缺少确认，模型的一个错误参数就可能变成真实副作用。

## 五、核心知识一：工具调用闭环

### 5.1 模型看到的是工具说明

模型根据名称、描述和参数 Schema 判断是否需要工具。

### 5.2 应用程序负责校验与执行

程序检查参数格式、业务范围、权限和确认状态，然后调用真实函数。

### 5.3 工具结果再次进入模型

结果应明确成功、失败和结构化数据，模型据此生成最终答复或决定下一步。
## 六、核心知识二：好的工具契约

### 6.1 名称表达单一动作

`search_course_notes` 比 `handle_data` 更明确。

### 6.2 描述同时说明“何时用”和“何时不用”

边界清楚能减少模型错误选择工具。

### 6.3 参数有类型、含义和限制

路径、数量、枚举和必填项都应明确；但 Schema 不能代替业务安全校验。
## 七、核心知识三：参数校验与权限

### 7.1 语法正确不代表业务合法

`limit=100000` 可能符合整数类型，却超过系统允许范围。

### 7.2 路径必须限制在白名单

即使模型生成了外部路径，程序也必须拒绝。

### 7.3 有副作用的动作需要更高门槛

写入、发送、删除应提供预览、人工确认和审计日志。
## 八、核心知识四：结果和失败也属于契约

### 8.1 返回结构应稳定

调用方应能区分 `ok`、`data` 和 `error`。

### 8.2 不把异常堆栈直接交给最终用户

应用记录技术详情，模型获得经过控制的错误信息。

### 8.3 记录每一次决策链

至少包含 run_id、工具名、脱敏参数、开始结束时间和结果状态。

## 九、讲师演示：为 Obsidian 课程资料设计安全的 search_notes 工具

### 演示任务

输入关键词，在允许的课程目录内搜索 Markdown 标题和正文，返回有限数量的相对路径。
### 第一步：先写契约

明确工具只读、只搜索白名单、limit 范围为 1～10，不负责读取全文或修改笔记。
### 第二步：实现双层校验

先做 Schema 类型校验，再做关键词非空、目录白名单和数量范围校验。
### 第三步：返回可审计结果

成功和失败都返回稳定结构，并记录调用日志。

### 演示代码／结构示例

```python
from pathlib import Path

ALLOWED_ROOT = Path("AI 授课").resolve()


def search_notes(query: str, folder: str, limit: int = 5) -> dict:
    query = query.strip()
    if not query:
        return {"ok": False, "error": "query 不能为空", "data": []}
    if not 1 <= limit <= 10:
        return {"ok": False, "error": "limit 必须在 1 到 10 之间", "data": []}

    target = Path(folder).resolve()
    if ALLOWED_ROOT not in target.parents and target != ALLOWED_ROOT:
        return {"ok": False, "error": "目录不在允许范围", "data": []}

    results = []
    for path in target.rglob("*.md"):
        text = path.read_text(encoding="utf-8")
        if query.lower() in text.lower():
            results.append(str(path.relative_to(Path.cwd())))
        if len(results) >= limit:
            break
    return {"ok": True, "error": None, "data": results}
```

> [!warning] 演示要求
> 代码用于说明结构，不绑定某一厂商或框架版本。授课时要现场运行或使用等价模拟，展示正常结果、一个失败结果和验证过程。

## 十五、本课总结

本课需要带走以下五点：

1. 工具调用是模型建议、程序校验执行、结果回传的闭环
2. 工具契约决定模型能否正确选择和填写参数
3. Schema 校验之外还必须有业务与权限校验
4. 副作用越大，确认、审计和回滚要求越高
5. 从只读、范围小、职责单一的工具开始最安全

## 十六、课后复习卡片

### 问：模型为什么不能拥有最终执行权？

答：模型输出具有概率性，应用程序必须依据权限、规则和确认状态决定是否执行。

### 问：工具越通用越好吗？

答：通常不是。边界越模糊，选择、校验、权限和失败处理越困难。

### 问：MCP 与本课有什么关系？

答：MCP 可以标准化暴露和连接工具，但不会自动替你完成权限、安全和业务校验。
