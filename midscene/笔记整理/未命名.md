## 一、提示词结构公式（强制推荐）

`[位置] + [颜色/大小/形态] + [控件类型] + [文字内容]`

> 公式拆解：在哪里 + 长什么样 + 是什么控件 + 上面写了什么

✅ 推荐示例：

- 弹窗右下角蓝色的【确认】按钮
- 页面顶部导航栏右侧，灰色文字【个人中心】链接
- 表单第二行，带灰色提示文字 “请输入手机号” 的输入框

❌ 反面示例（不要写）：

- 点击确认按钮（缺少位置，页面多个确认按钮会点错）
- 点击 `.submit-btn`（AI 看不到 css 类，无效）
- 点击 id=login 的元素（DOM 信息，Midscene 不读 DOM 定位）

## 二、各类型控件提示词模板，直接套用

### 1. 按钮（aiTap 最常用）

模板：`[区域] + [颜色/形状] + 按钮 + [按钮文字]`

- 主按钮：弹窗底部蓝色矩形【提交】按钮
- 次要按钮：弹窗底部灰色【取消】按钮
- 图标按钮：表格行最右侧铅笔形状的编辑图标按钮

### 2. 输入框（aiInput）

模板：`[位置] + 输入框，提示文字是“xxx”`

- 表单第一行输入框，占位文字 “请输入用户名”
- 弹窗内密码输入框，灰色提示 “不少于 6 位”

### 3. 文本 / 断言（aiAssert）

模板：`[位置] + 文字内容 + [样式，可选]`

- 输入框下方红色文字：手机号格式不正确
- 页面标题，黑色大号文字：用户管理列表

### 4. 等待（aiWaitFor）

模板：`等待 [位置] 出现 [内容/控件]`

- 等待加载弹窗消失
- 等待表格列表数据展示完成
- 等待右上角 “加载中” 转圈图标消失

### 5. 提取文本（aiString）

模板：`[位置] + 需要提取的文字`

- 表格第一行，姓名列的文本
- 弹窗标题栏的文字

## 三、增强提示词的加分技巧（降低误识别）

1. **优先写相对位置**：左、右、上方、下方、弹窗内、表格行内、表单第二行

> 页面存在多个同名按钮时，位置是区分元素最重要信息。 例：弹窗内【确认】 vs 页面主区域【确认】，AI 很容易搞混。

2. **区分控件特征**：文字按钮 / 图标按钮 / 单选框 / 复选框 / 下拉选择器

> 不要统一叫 “按钮”，复选框就写复选框，下拉框就写下拉框。

3. **描述状态（可选）**：置灰、高亮、红色、必填星号 *

> 例：表单底部置灰的提交按钮（用来断言按钮不可点击）

4. **限定范围**：当页面有多个模块，限定在某个容器内

> 例：在【筛选条件】模块，点击【重置】按钮

## 四、禁止写进提示词的内容（黑名单）

不要写任何下面这些，AI 视觉模型无法读取，写了只会干扰：

1. DOM 相关：xpath、css selector、id、class、data-testid
2. JS 属性：disabled、value、href
3. 前端内部术语：div、span、input 标签
4. 像素坐标：x:100 y:200（页面缩放会失效）

## 五、常见场景对比：坏提示词 → 好提示词

表格

|场景|❌ 较差|✅ 优化后|
|---|---|---|
|弹窗确认|点击确认按钮|弹窗右下角蓝色【确认】按钮|

## 六、稳定性优化策略（测试落地重点）

### 6.1 页面元素相似怎么办？

页面有多个长得几乎一样的按钮：**增加父容器范围描述**

> 坏：点击删除按钮 好：第一条数据行最右侧红色【删除】按钮

### 6.2 页面动态元素、弹窗

优先限定：`弹窗内`，弹窗是独立视觉区域，AI 更容易隔离。

### 6.3 提示词不要太长

描述精准，但不要冗余，一句话搞定。太长的描述会增加模型理解负担。

### 6.4 先用 Playground 调试提示词

> 流程：打开页面 → 在 Midscene Playground 输入你的提示词 → 执行 ✅ 能正确识别元素，再把提示词复制到脚本 / YAML ❌ AI 识别失败，立刻优化描述，不要直接写进自动化脚本。这是最高效的调试习惯。

## 七、断言提示词两种写法（区分业务校验）

Midscene 的`aiAssert`分两类，测试要分清：

1. **存在性断言（推荐）**：校验页面有没有看到内容 `aiAssert("页面弹窗显示文字：操作成功")`
2. **样式断言（UI 回归）**：校验颜色、排版 `aiAssert("错误提示文字是红色，位于输入框正下方")`

> ⚠️ 重要提醒：**业务数据正确性，优先接口断言；Midscene 只断言 UI 可见表现**。 例：新增用户，不要靠 aiAssert 判断数据库是否新增成功，调用接口查数据库；Midscene 只断言页面弹出 “新增成功”。

## 八、常见坑 & 应对方案

1. AI 识别错元素：增加**位置描述**，区分多个同类控件
2. 偶现不稳定：在操作前加`aiWaitFor`等待页面稳定，不要直接点击
3. 页面动态渲染：等待 loading 消失，再执行下一步
4. 页面缩放 / 窗口大小影响：脚本固定 viewport，保持截图大小一致

## 九、提示词评审检查清单（写好用例后自查）

写完一句提示词，自问 3 个问题：

1. 如果我是第一次看这个页面的人，仅凭这句话能不能定位到元素？
2. 页面是否存在同名控件？有没有加位置区分？
3. 是否包含 DOM/css/id 等无效信息？
